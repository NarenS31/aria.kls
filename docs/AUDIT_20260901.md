## 3. What is actually implemented — verified by reading code

**Definition used here.** *The main reasoning path* = `launch_aria.sh` →
`main.py:372` → `ARIAAgent` (`agent/reasoning.py:487`) → `ui/app.py`. A module is
**WIRED IN** if it is reachable from that path; **ORPHANED** if it exists but
nothing on that path (and, where noted, nothing at all) calls it.

### 3.1 The finding that governs most of this section

`agent/reasoning.py:2124` splits `think_aloud_turn` into two mutually exclusive
implementations:

```python
if not getattr(self, "profile", {}).get("full_research_metacognition", False):
```

`grep -rn "full_research_metacognition" --include="*.py" --include="*.json" --include="*.md" .`
returns **exactly one code hit — that line itself.** No profile JSON in
`data/profiles/` sets it; no test sets it; nothing writes it. The flag therefore
always reads `False`, so:

- **The product always takes the first branch** (`reasoning.py:2124–2225`), which
  uses `_quick_thinking_state` → `understand_student_turn` → `_build_situation_model`
  → `_situation_policy_response`.
- **The second branch (`reasoning.py:2227–2388`) is unreachable in the product.**
  That branch is the only place `CognitiveStateAnalyzer`, `MetacognitiveInterventionGenerator`,
  `MetacognitionTracker.record_state`, and `InterventionTimer.should_intervene`
  are consulted during a turn.

A second, subtler gate: `_init_metacognition()` (`reasoning.py:555`) is only
called from `__init__` when `think_aloud_mode=True` (`reasoning.py:548`).
`main.py:372` — the Gradio product path — **does not pass that argument**; only
`main.py:264` (the `--think-aloud` console loop) and `eval/rq2_pipeline.py:268`
do. So on a freshly launched GUI session, `self._meta_transfer` is `None` and the
`if self._meta_transfer is not None:` guard at `reasoning.py:2172` skips transfer
detection entirely — until the student opens the metacognitive-development
dashboard, whose accessors (`ui/app.py:877`, `889`, `901`) call
`agent.transfer_detector()` / `calibration_tracker()` / `intervention_timer()`,
each of which calls `_init_metacognition()` as a side effect
(`reasoning.py:2446, 2451, 2456, 2461`).

## 9. Honest summary

### 9.1 Genuinely done and verified

- **The test suite passes completely.** 190 tests, 190 passing, 0 failing, 0
  erroring, 0 skipped — run during this audit, not remembered (§7).
- **The problem-disjoint evaluation (2026-08-26) is real and independently
  checkable.** All 21 checksums verify against the files on disk *and* against
  the classifier source files. Leakage checks are all zero across 12 tests over
  50 problems and 8,750 utterances. Environment, git commit, package versions,
  and a determinism argument are all recorded. ECE is deliberately not reported,
  with a written reason. This is publication-grade provenance.
- **The LLM-fallback ablation (2026-08-27) is real, and reports a negative
  result about its own system.** All 18 checksums verify. The few-shot audit
  self-declares `leakage: true` and names the leaked problems (P14, P39), which
  is why the run carries both a contaminated and a decontaminated arm. Every arm
  that turns the LLM on is **worse** than lexical-only, and the artefact says so.
- **The seven-state classifier's synthetic-corpus numbers are stable and
  reproducible from files**: 0.8457 accuracy / 0.837 macro-F1 on the 350-item
  test split, heuristic-only, 100% of examples routed away from the LLM.
- **The cross-generator weakness is measured, not hidden.** phi3:medium costs
  23–25 accuracy points depending on the sampling condition; the gap on gemma2
  has a CI that includes zero in the matched analysis.
- **The behavioral-fusion layer is honestly reported as a null result**: it
  changed 7 predictions out of 3,507 (0.2%) and moved macro-F1 by 0.0021.
- **The external-dataset work is honest about what failed.** 7 datasets mapped,
  3 usable; the other 4 are marked `computable: false` with a per-dataset reason
  rather than being reported as zeros.
- **The task bank exists and is wired in**: 100 tasks with answer keys, solution
  steps, key ideas, and misconceptions, loaded on the live product path and
  asserted at 100 by a test.
- **The closed-loop model comparison is a genuine null**: both models reach
  composite 1.0 in the full pipeline, the treatment−base difference on student
  grounding is 0.0, and the distilled model is 2× slower (9.78 s vs 4.69 s).
- **The claim ledger (`eval/CLAIM_LEDGER.md`) is unusually disciplined** and, on
  the points I could check, accurate — including the row that says the distilled
  model's result is "Contradicted by current evidence."

### 9.5 The one-paragraph version

ARIA is a working local tutoring product plus a substantially more rigorous
evaluation harness, and the two have drifted apart. The evaluation side has
genuinely good work in it — checksummed, leakage-audited, negative-result-honest
— but almost all of it measures a seven-state classifier that the product stopped
calling at commit `a5f663f` (2026-07-30, "Replace cognitive states with
task-grounded situations"). The product's own replacement — the situation model
and its policy — has 37 unit tests (`tests/test_situation_model.py` 15,
`tests/test_product_reliability.py` 22) and no evaluation against any labelled
data at all. Everything requiring another human being (educator ratings, annotator
labels, RQ2 responses, IRB, students) is fully prepared and entirely uncollected:
552 blank rating rows and a form that was never published. The test suite is
green, the newest results are trustworthy where they are checksummed, the two
best result sets are sitting on unmerged branches, and the generated evidence
documents are one to two evaluation rounds behind the artefacts they summarise.
