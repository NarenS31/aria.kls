### Top-level module descriptions (from reading the files, not filenames)

| Module | What it actually contains |
|---|---|
| `main.py` (399 lines) | Terminal intake wizard, Ollama health check, and CLI dispatch to four modes: Gradio UI (default), `--think-aloud` terminal loop, `--train-lora`, `--train-distilled`. |
| `agent/` | The live reasoning behaviour: `reasoning.py` (2,847 lines) is a LangGraph agent holding the coaching loop, the `SituationModel` dataclass, and the metacognition bootstrap; the other 7 modules are emotion pacing, nudge scheduling, a persistent learner model, closed-loop intervention selection, regex reasoning-move extraction, and student-intent/understanding parsing. |
| `memory/` | Local persistence: a ChromaDB conversation vector store, a NetworkX per-topic learning graph, an ADHD-modified SM-2 spaced-repetition scheduler, and a session checkpoint writer. |
| `knowledge/` | Document ingestion into per-folder ChromaDB collections, plus text extraction for PDF/TXT/MD/MP4/MP3/YouTube and a folder index. |
| `shared/` | Cross-cutting utilities: a shared curriculum/notes knowledge base, PDF+CSV report generation, and profile CRUD across SRS/graph/emotion/checkpoint stores. |
| `ui/` | `app.py` (1,110 statements) is the Gradio student + research console (chat, think-aloud panel, confidence rating, seven matplotlib dashboards); `menubar.py` is a macOS menubar wrapper with an Option+Space hotkey. |
| `lora/` | Local model-adaptation tooling driven by `mlx_lm` via `subprocess`: per-profile adapter training, a distillation adapter, a dataset formatter, and a 4-condition (vanilla / RAG / LoRA / distilled) comparison harness. No trained adapters are present. |
| `papers/` | `aria_paper.py` auto-generates `aria_paper.md` from `data/experiment_results_full.json` + `data/failure_patterns.json` using llama3.1:8b. |
| `reports/` | Teacher/parent report generator plus one committed sample report. |
| `scripts/` | Two build scripts: the 100-task answer-keyed practice bank, and the student-intent classifier trainer (writes `models/student_intent.joblib`). |
| `models/` | One trained artifact: a scikit-learn intent classifier + its metadata/eval card. |
| `research/` | 16 protocol/ethics/preregistration Markdown documents, 3 consent templates, a task-model JSON schema, and 3 blank reviewer packets. All prospective; no collected data. |
| `eval/` | Two things in one tree: (a) the metacognition engine `eval/metacognition/` that `agent/reasoning.py` imports at runtime, and (b) ~45 standalone evaluation/analysis scripts plus `eval/eval/` (12 experiment runners) and `eval/datasets/` (registry + 14 external-corpus adapters). |
| `data/` | Product-local state (profiles, graphs, chroma, SRS) plus committed research artifacts (question bank, RQ2 stimulus set + answer key, experiment results, figures). |

### The wiring rule that governs most of this section

`agent/reasoning.py:2124` is the branch that decides the product's behaviour:

```python
if not getattr(self, "profile", {}).get("full_research_metacognition", False):
```

`grep -rn "full_research_metacognition"` over the whole repo returns **exactly
one hit — that read site**. No profile JSON, no script, no test ever sets it.
So the `False` branch (lines 2124–2224) is the only path the product takes, and
lines 2226+ are dead in the product. The code says so itself at
`agent/reasoning.py:2226-2227`:

> `# Historical experiment compatibility only. The product path above does`
> `# not expose or depend on this legacy cognitive-state evaluator.`

Separately, `_init_metacognition()` (`agent/reasoning.py:555`) is only called
when `think_aloud_mode=True` at construction, or lazily via
`transfer_detector()` / `calibration_tracker()` / `intervention_timer()` /
`set_confidence()` (lines 2449–2462, 2007). `main.py:372` constructs the agent
**without** `think_aloud_mode`, so those objects are `None` until the UI touches
a dashboard or a confidence rating.

## 9. Honest summary

### Genuinely done and verified

- **A working product path.** `main.py` → `ui/app.py` → `agent/reasoning.py`

  situation model, the closed-loop intervention pipeline, the 100-task answer-keyed

  UI, and 129 tests covering them pass under Python 3.11.

  result unfavourable to the system: mean gap 9.05 pts, phi3 at 24.0

  not softened.

  reports, per dataset, that **4 of 7 yield no state at all**, with a specific
  field-level reason for each (`external_validation_multi_dataset.json`). Not
  pooled, not averaged.

  effectiveness "Unsupported", and diagnosis "Prohibited". The closed-loop
